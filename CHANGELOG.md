# Changelog

WildINTEL project provides up-to-date release notes for the CamTrap Verify application on all supported platforms. This
document contains information about recent changes, including new features, bug fixes, and improvements. It is intended to 
help users and developers understand the evolution of the project over time. 

You can download the latest version of CamTrap Verify from the [releases page](https://github.com/wildintelproject/wildintel-trapverify/releases).

To report a bug or request a new feature, please open an [issue](https://github.com/wildintelproject/wildintel-trapverify/issues).

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),  and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Upcoming release

#### Added
- **Large view: previous card and progress panel.** `Backspace` (or the **↶ Previous card** button) goes back through the cards decided since the large view was opened, to correct a mistake. A panel on the left shows the progress (round, cards decided in the round with a bar, cards decided at the current location, occasions of the species resolved before the round) with the decision buttons (Confirm, Reject, Uncertain) stacked next to it and a reminder of the keys; screens narrower than 900 px keep the buttons in a strip at the bottom. A **Large view** button in the header opens it at the first undecided card, also when reviewing a finished species.
- **Save progress automatically and go back a round.** The decisions of an unfinished round (confirmed, uncertain, typed actual species, decision times) are saved in `decisions/progress_<species>_iter<N>.csv` a couple of seconds after each click, with a **Save progress** button and when the page closes, and are restored when the species is opened again from any browser or, through the session export, another computer. They change no result until the round is finished (the main button is now **Finish round**). **← Back to round N** reopens the last finished round with its decisions (`POST /api/species/{species}/reopen`); the round's files are kept in `decisions/reopened/`, finishing it again gives the same files as deciding it once, and the later round's progress is kept. Not available after the species' decisions were edited as a whole.
- **Export and import a session** to continue it on another computer: **Export session** (species index) downloads a ZIP with the review state only (`config.json`, candidate manifest, decisions, review log, corrections and exclusions; no photos, no outputs), and **Import session…** (welcome screen) opens it in a new folder. Only known file names are extracted (anything else, absolute or `..` paths included, is ignored). Sessions store a `dataset_fingerprint` (hash of `deployments.csv`); when the data folder is not found, the app reuses the folder of another local session on the same dataset, or asks for the right folders (**Fix links**). Pointing a session at a different dataset is refused.
- **Session names**: an optional *Session name* in the setup parameters (`session_name` in `config.json`, up to 120 characters, whitespace collapsed), shown in **Recent sessions** (with the species below it) and at the top of the species index. Any recent session, or the active one, can be named or renamed later with **✎** (`PUT /api/session/name`; an empty name clears it). Only the active session or one in the recent list can be renamed, and `config.json` is rewritten whole, so the endpoint cannot be used to write files elsewhere. A new session never inherits the name of the previous one when the setup form is pre-filled. Sessions without a name look as before.
- **Minimum detection confidence per species** (`min_score_by_species` in `config.json`; setup parameters, a collapsible list under the general score): any target species can have its own cut-off, which replaces the general `min_score` for that species (an empty box uses the general one; `0` turns the cut-off off for it, also when the general one is higher and without dropping negative scores). A score equal to the cut-off is kept, as before. The report of what the cut-off left out now follows each species' own cut-off: `min_score_exclusions.csv`, `effort_report.csv` (new `min_score` column, the cut-off that applied) and the Results table, which gets a *Cut-off* column and a note when species have their own. The gallery text shows the cut-off of the species being reviewed. A species that loses every photo to its cut-off is still reported (it used to disappear from the table), and a setup that leaves **no** candidate at all now returns a clear error instead of failing with a server error. Existing sessions and configs without the field work unchanged.
- **Finding photos in more layouts.** When a photo is not at `Images directory/deploymentID/fileName`, the app now also looks for **the end of `filePath`** under the Images directory (a `media.csv` exported on another computer, e.g. `/Volumes/Disk/2023/R0025/dep_0011/x.jpg`, works on Windows by pointing the Images directory at the folder holding `R0025/`; `/` and `\` both accepted), then for **a folder named like the `deploymentID`** up to three levels below it (`Images directory/R0025/dep_0011/`), with the file matched ignoring case and equivalent extensions (`.JPEG` is found as `.jpg`). A photo found in two such folders is not used. This finds the photos of Trapper-style exports, whose `filePath` is a web address. The flat search (*Search subfolders by file name*) now also ignores the extension difference. The setup image check, the gallery and the image route all use the same lookup.
- When the Images directory is set but the photo is not there, the end of `filePath` is also tried under the data directory and under the **parent** of the Images directory, so picking the `camtrapDP` folder itself (one level too deep) no longer hides every photo; without an Images directory it is tried under the data directory. The lookups use small caches of folder listings (cleared on every new session); faster bulk checks for very large archives are a separate issue.
- **Verification effort by species**: new `effort_report.csv` in `occupancy_inputs/` (one row per species plus a `TOTAL` row) and a table on the Results page. It reports effort in detection events and cells, split by outcome: cells with and without detection, events inspected in each kind of cell, rejections before the first confirmation (mean, median, max), and the score of rejected and confirmed events (min, median, max). "Inspecting" an event means viewing its top-scoring photo; `candidate_events` is the event-level full-review baseline. Photos are reported too (candidate photos and photos in the inspected events). Cells still pending rounds are reported as unverified.
- **Effect of the minimum-score cut-off**: for each species the app now reports what the cut-off removed before review: excluded photos, excluded detection events and cells left with no candidate (`excluded_photos`, `excluded_events`, `excluded_cells` in `effort_report.csv`, written from `min_score_exclusions.csv` in the session folder). When `min_score > 0`, Results shows a notice (savings and results apply only to candidates at or above the cut-off) and a table of the excluded counts. A score equal to the cut-off is kept; with no cut-off every count is 0. Creating a session with a cut-off runs the candidate build twice to measure it, which lengthens setup on very large archives. Older sessions have no exclusion counts (shown as –). The manual explains when a cut-off should and should not be used.
- **Maintenance and community contribution policy**: `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1), `SECURITY.md`, bug-report and feature-request issue templates and a pull-request template; a new *Maintenance and support* page in the documentation and a section in the README (maintained within the WildINTEL project, which initially ends at the end of 2027, and open to community contributions on GitHub; supported versions; how to get support). The Developer Manual is referenced as the guide for new contributors and now documents the Zenodo DOI step of the release process.
- **Uncertain decision**: a third button (and `U` in the lightbox) for detection events whose label is possible but uncertain. For occupancy it behaves exactly as a rejection (detection histories are identical to rejecting it), but it is recorded in `decisions/uncertain_<species>_iter<N>.csv` and reported per species: `uncertain_events` and `non_detection_cells_with_uncertain` in `effort_report.csv` and a column on Results. `POST /api/decisions` accepts an optional `uncertain` list and `GET /api/decisions` returns it. Existing sessions load unchanged (no uncertain files means zero). The manual now states the recommended guidance: if the species cannot be confirmed with reasonable confidence, do not confirm it.
- **Record the actual species when rejecting** (setup option `record_rejection_species`, off by default): rejected detection events get an optional *Actual species* field in the gallery and the large view, with suggestions from the dataset's taxa plus *Homo sapiens* and *No animal / empty* (free text allowed). The review is unchanged: a rejection is still a rejection, `N` still rejects without opening anything, and the detection histories are identical with the option on or off (a rejected event relabelled as another species is not counted as a detection of it). Values go to `rejection_corrections.csv`; `occupancy_inputs/false_positive_sources.csv` and a table on Results give the main false-positive sources per species, with a *not recorded* row for rejected events without a value. `POST /api/decisions` takes an optional `corrections` map, `GET /api/decisions` returns it and `GET /api/taxa` lists the dataset's taxa.
- **Review time**: the time of each decision is now recorded (taken in the browser when the reviewer clicks) in `review_log.csv`, and the **active review time** is reported per species and in total on Results and in `effort_report.csv` (`review_active_seconds`, `review_decisions_timed`, `review_seconds_per_decision`), together with an *estimate* of a full event-level review (candidate events × mean seconds per decision) and of the time saved. Pauses longer than the new setup option *Idle threshold for review time* (`review_idle_seconds`, 120 s by default) are breaks and are not counted; the time before the first decision of each work block is not observable, so the result is a slight underestimate. `POST /api/decisions` takes an optional `decision_times` map. Decision files are unchanged and sessions without timestamps show *n/a*.
- **`uv run cli simulate-random <session>`**: simulates, on a finished session, reviewing the same number of photos at random (`--draws`, default 1000, and `--seed`, default 42, for reproducibility) and reports per species how many of the cells with a detection a random subsample would find compared with the targeted workflow (mean and range across draws, and as % of the detection cells), in `random_subsample_simulation.csv`. It tests the claim that a random subsample of the same size would leave most cells unresolved. Documented in the Developer Manual, with an example in `examples/simulate_random_example.py`.
- **Confidence intervals for the detection probability**: the occupancy table on Results and `occupancy_inputs/occupancy_fit.csv` now give the 95 % confidence limits of **p**, naive and verified (`p_naive_lo`, `p_naive_hi`, `p_verified_lo`, `p_verified_hi`), so all four estimates (ψ and p, naive and verified) have intervals. The manual explains the model, the ψ(.)p(.) notation and the method in plain language, and `occupancy_model.py` states it precisely so it can be cited.
- **Scope and limitations** (user manual section 9 and the features page): what the tool assumes and does not do. It needs an existing classifier or labels; it reads still images only (with guidance for extracting frames from video, not tested on video data); it is designed for occupancy models, with the limits for event counts, activity patterns, abundance and time to first detection; what the score needs to be (any ordering value works, raw logits need the minimum score set to 0, photos without a score count as 0, and without scores, or among equal scores, the events are shown in a seeded random order); guidance for reviewers (uncertain cases, documenting who reviewed and double verification); that false negatives are not corrected; and that photos with several labels are shown whole, without the box.
- **Bounding boxes in the review**: when `observations.csv` has the CamtrapDP columns `bboxX`, `bboxY`, `bboxWidth` and `bboxHeight` (relative 0–1), the box of the animal being verified is drawn on the photo in the gallery and the large view, so photos with several animals or labels show which one is meant. The box of the species being reviewed is amber; other boxes of the same species in the photo are thinner and lighter; boxes of other species are not drawn. It is drawn by the server into the image sent to the browser (`GET /api/image/{mediaID}?boxes=true&obs=<observationID>`), so it follows zoom, rotation, inversion and fullscreen; the files on disk are not changed. A *Show boxes* checkbox appears when the data have boxes (remembered in the browser). Candidates now carry a `bboxes` column, a *Custom CSV* that has the box columns keeps them (the DeepFaune CSV has none), and invalid boxes are ignored. Photos with no box, and remote images, are shown as before. Adds **Pillow** as a runtime dependency.
- **Sampling occasions in hours** (setup option *Sampling occasion duration* with a *Days / Hours* selector, `occasion_hours` in `config.json`; 0 keeps days): for example 1-hour occasions to verify one record per species, location and hour for **activity patterns**. The windows start at 00:00 of the first day; `camera_operation.csv` gives the hours of operation per window (a date without a time covers the whole day); occasions with the camera off are NA in the detection histories. With occasions shorter than a day the occupancy estimate is **not computed** (it is not meaningful at that resolution) and Results says so. Sessions made before this option existed work as before. The manual describes the use and its limits, and the section on other analyses now points to it for activity patterns.
- **`LICENSE`**: the GNU General Public License v3.0 text, which the README already linked to but the repository did not contain.
- **Weekly dependency check** (`.github/workflows/scheduled.yml`): tests the backend and frontend against the latest compatible dependencies every Monday and opens (or updates) a `dependency-check` issue if they fail. Dependabot (`.github/dependabot.yml`) proposes Python, npm, GitHub Actions and Docker updates against `development`.

#### Changed
- **Faster backend on large archives.** Profiled first, then fixed what dominated: the effort report and review effort no longer walk the cells one by one (vectorised, checked against the previous implementation on random data), burst assignment is vectorised, the gallery payload no longer re-sorts every cell, image requests use an in-memory index instead of scanning the manifest, and `datapackage.json` validation checks the first 50,000 rows of each table. **Saving a round no longer rewrites `camtrap_dp_verified/`**: it is marked stale and rebuilt when the Results page is opened, the results are downloaded or the session folder is opened. The app's own image URLs carry a per-session token (`?v=`) and are cached by the browser; bare URLs stay `no-store`. Outputs are identical (23 files and the results compared on a 3-round session). On 96,166 photos / 1,124 cards: create the session 37.2 → 5.1 s, list the events 4.9 → 0.8 s, save a round 21.9 → 0.6 s, open the results 7.0 → 1.6 s (including the rebuild of the verified CamtrapDP). `scripts/benchmark_backend.py` reproduces the numbers.
- **Faster gallery for large rounds.** The gallery shows **one location at a time** (previous / next / selector with the progress of each location), and each card renders **a single photo** with ‹ › arrows instead of a carousel with every frame; cards are memoised, so a decision re-renders one card. `swiper` is no longer a dependency. **Confirm all** now confirms the location being shown (**Confirm all in this location**). On a synthetic round of 1,147 cards and 5,212 photos: DOM nodes 53,574 → 506, `<img>` 5,212 → 20, click-to-paint about 340 ms → 33 ms (one frame). Opening the page still waits for the server to list the events (about 4.5 s here); that part is not changed by this.
- **Times are shown to the second** on the gallery cards and in the large view (they showed minutes), so the order of frames taken in the same second can be checked. Sessions saved with minutes show seconds too.
- **The large view scales photos up to fill the screen** (they were shown at most at their own pixel size), switches between frames and events instantly (no slide or fade animation) and preloads the next frames; a gallery card preloads its neighbouring frames once the pointer is over it, so the arrows do not flash an empty frame.
- **Detection events with the same score are now ranked in a seeded random order** instead of by chronology (a tie, including every event when the photos have no score, used to fall back to the order of the data, i.e. the earliest event first). The order depends only on the seed, the cell and the event, so the same data and seed always give the same order. The seed is the new setup parameter *Random seed for tied detection events* (`random_seed`, 42 by default) and is stored in `config.json`. Scored events are ranked exactly as before, and existing sessions keep the order already saved in their candidate manifest.
- **Occupancy confidence intervals** are now Wald intervals on the logit scale with the standard errors taken from the exact (finite-difference) Hessian at the maximum. They used the inverse-Hessian approximation that BFGS keeps while optimising, and the code comment called them profile intervals, which they never were. On simulated data the old and new intervals have similar coverage (about 95–97 %), so published values should change little, but ψ intervals of existing sessions can differ slightly when the session is reopened and the fit is recomputed.
- Contribution pull requests are now documented as targeting `development` (the Developer Manual said `main`). CI and the README now use Node.js 22, the version of the frontend Docker image (they said 20 and 18+).

#### Fixed
- Once a species is complete, the review screen showed every confirmed cell with its **rank-1 detection event**, even when the event actually confirmed came from a later round. Confirmed cells now show the confirmed event, with its real rank. Editing the decisions of a completed species (**Update decisions**) also kept rank 1 as the confirmed record of every cell, which changed the effort figures; cells that stay confirmed now keep the event that was confirmed.
- **Update decisions** on a completed species reset its round count: only a first round was kept, so every unconfirmed occasion with more than one detection event re-opened for review and showed as unverified on Results. The number of rounds done is now preserved.
- Opening a species in the gallery **always showed round 1**, which re-presented occasions already rejected in earlier rounds. The gallery now opens at the species' current round, the one the index shows.
- **Frames taken in the same second kept their capture order only when `filePath` ended in the file name.** Exports that keep a web address there (e.g. Trapper, `.../media/4897674/file/`) could lose the order of such frames. The capture number is now read from `fileName` first (an optional CamtrapDP field: when it is absent or empty the end of `filePath` is used, and without a number anywhere nothing is reordered) and every later re-sort of the frames keeps it, so sessions saved before also show the right order.
- The directory picker's breadcrumbs now work with Windows paths (`D:\...`).
- `uv run cli dev` (and the other `cli` commands that run npm) failed on Windows: tools were located with the Unix `which` and `npm` was started by its bare name, which Windows cannot do for `npm.cmd`. Both now go through `shutil.which`.
- **The last, shorter sampling occasion lost detections.** When the study period was not a multiple of the occasion length (for example 12 days in occasions of 5), the photos of the last, shorter occasion were merged into the previous one (the first day) or dropped (the others), although the occupancy matrices did include that occasion. Occasions are now assigned by timestamp with the same windows as the occupancy inputs. Studies whose length is a multiple of the occasion length (such as 30 days in occasions of 5) were not affected.
- `@testing-library/dom`, a required peer dependency of `@testing-library/react`, is now declared in `frontend/package.json`; it was only present through `package-lock.json`, so installs that ignore the lock file failed to type-check and run the frontend tests.

### [0.4.2](https://github.com/wildintelproject/wildintel-trapverify/compare/v0.4.1...v0.4.2) - 2026-08-18

#### Fixed
- Gallery images whose `filePath` is a remote URL (e.g. a TRAPPER export) are now resolved locally first when an **Images directory** is set — the structured `image_base_dir/deploymentID/fileName` lookup used to only apply to local `filePath` values, so a remote-but-already-downloaded photo always hit the network proxy and 404'd for anyone without access to the source server.
- DeepFaune and Custom CSV imports no longer bake `filePath` into an absolute path at conversion time; both now write the CSV's own relative path plus a `fileName` column and go through the same **Images directory** resolution as a plain CamtrapDP directory, instead of a separate one-shot mechanism the wizard never let you revisit.
- When no **Images directory** is set, relative `filePath` values now resolve by default against the directory the CSV files (`deployments.csv`/`media.csv`/`observations.csv`) are actually in, instead of its parent — for every source, not just plain CamtrapDP.
- Confirming or rejecting a detection event in the fullscreen lightbox now advances to the next undecided occasion at the **same site**, instead of jumping to whichever site happens to come next in the underlying list — the auto-advance logic scanned the flat events array in order, which interleaves sites, unlike the Arrow Up/Down navigation, which already stayed within the current site.

#### Changed
- User manual refreshed throughout: Setup Wizard steps 1–4, Species Index, Image Gallery and Results sections now match the current UI (updated terminology, new/removed fields, missing screenshots added), including a new explanation of how image paths are resolved and in what order.

### [0.4.1](https://github.com/wildintelproject/wildintel-trapverify/compare/v0.4.0...v0.4.1) - 2026-07-30

#### Added
- `scripts/anonymize_repo.py`: exports an anonymized snapshot of the repo (via `git archive`, so no commit history or author metadata) for double-blind review. Strips author names/emails, this repo's own GitHub URLs, project branding, and funding/grant identifiers using the redaction map in `scripts/anonymize_repo.config.json`; genuinely external dependencies (fastapi, pandas, ...) are left alone, but `wildintel-trapper-sdk` -- another WildINTEL repo, not a third-party package -- is vendored and anonymized locally too via `--vendor wildintel-trapper-sdk=<path>#<ref>` (`scripts/anonymize_trapper_sdk.config.json`), with `uv.lock` regenerated against the vendored copy so the exported app still builds and runs. The tooling's own config (which would otherwise contain the real org/repo URL as literal data) is excluded from the snapshot outright rather than relying on self-redaction, and a hard `verify_no_leaks()` gate aborts the run (no zip produced) if any real value from either redaction map is found anywhere in the output. Also rebuilds `backend/site/` so the in-app Help button, repointed at the local `/docs/` mount, still resolves to a (now-anonymized) manual instead of leaking the public docs site.
- `setup.ps1`: PowerShell equivalent of `setup.sh` for Windows -- checks Docker, installs `uv` if missing, runs `uv sync`, and installs frontend dependencies via `npm`.
- `uv run cli docs pdf` (and `backend docs pdf` / `frontend docs pdf`): builds the documentation as a single PDF via `mkdocs-with-pdf`/WeasyPrint, only when explicitly requested (`ENABLE_PDF_EXPORT=1`) so normal `docs serve`/`docs build` don't pay the render cost.

#### Changed
- Renamed "sampling period" to "sampling occasion" and "sequence" to "detection event" throughout the UI, documentation, and translations (en/es/de/pl), matching the occupancy-modeling vocabulary already used internally. Updated the corresponding user-manual screenshots.

#### Fixed
- `deployments.csv`/`media.csv`/`observations.csv` are now located via the `path` each resource declares in `datapackage.json` (resolved relative to its own directory) before falling back to the `{name}.csv`/`{name}.csv.gz` naming convention. Packages using non-standard file names, or shipping only gzip-compressed tables (e.g. some Trapper exports), previously failed to load even though the descriptor already pointed at the right files.
- `uv run cli` (and every subcommand) silently ran `wildintel-trapper-sdk`'s own management CLI instead of this project's: both installed a top-level module literally named `cli`, and since the dependency installs non-editably (a physical `cli.py` in `site-packages/`) while this project installs editably (a meta-path finder, checked after the standard one), the dependency's always won. Renamed this project's own script `cli.py` → `manage.py` (`[project.scripts]` still exposes it as the `cli` command, only the underlying module name changed) so the two can never collide again.

### [0.4.0](https://github.com/wildintelproject/wildintel-trapverify/compare/v0.3.0...v0.4.0) - 2026-07-27

#### Added
- Optional **Images directory** field in the CamtrapDP setup flow: when provided, relative `filePath` values in `media.csv` are resolved against this directory instead of the parent of the data directory.
- **Download results** button on the Results page: generates a ZIP file of the full session directory (`wildintel-camtrap-verify-{session_id}.zip`) and triggers a browser download.
- macOS DMG package (`camtrap-verify-X.Y.Z-macos-arm64.dmg`) added to the release workflow for Apple Silicon.
- GitHub repository link (icon, stars, forks) added to the documentation header via `repo_url` in `mkdocs.yml`.
- `CHANGELOG.md` with release history following the Keep a Changelog format.
- Release notes section in the developer manual describing the full release process.
- `flat_search` option added to the setup request schema and workflow config (backend/frontend type wiring for a non-recursive directory search).
- Optional **Output directory** field in the setup wizard's Parameters step, with a directory browser, so a session's folder no longer always defaults silently to `~/Documents/camtrap_verify` — the backend and its config already supported a custom `output_dir`, but no UI ever exposed it.
- When a source directory (local pick or Trapper download) already ships a `datapackage.json`, `/api/fs/inspect` now validates it with `frictionless` and the setup wizard shows any schema/data errors as a non-blocking warning — helps catch a malformed source package instead of silently working around it.
- When the source package has no `datapackage.json` at all (converted from a DeepFaune/generic CSV, or a CamtrapDP source that simply never had one), `export_verified_camtrapdp()` now generates a best-effort default via `generate_default_datapackage()` instead of leaving the exported package without one. It derives `temporal`/`taxonomic`/`project.observationLevel` from the data and `spatial` from `deployments.csv` coordinates when present, and invents placeholders for everything it can't know (`contributors`, `project.title`/`samplingDesign`/`captureMethod`/`individualAnimals`, `spatial` when no coordinates exist). The Results page shows a warning listing exactly which fields were invented, read from the generated file's `wildintelGenerated.fabricatedFields` marker — the process is never blocked by a missing or invented descriptor.

#### Changed
- `export_verified_camtrapdp()` now also copies `datapackage.json` unchanged into `camtrap_dp_verified/` when the source package has one, instead of dropping it — only the values in `observations.csv` change, not its schema, so the original descriptor still describes the exported package correctly and it stays usable by other CamtrapDP tools.
- **Show all event frames** (formerly *Show event context images*): reworked logic so that only frames captured between the first and last detection of the target species are included, preventing frames from adjacent animal visits from appearing in the carousel.
- **Gallery review cards** now open on the sequence frame with the highest detection confidence instead of the chronologically first one; the zoom button opens the lightbox at that same frame instead of always the first.
- The Trapper integration (`trapper_service.py`) now uses `wildintel-trapper-sdk` instead of a hand-rolled `httpx.AsyncClient` wrapper, with SDK calls run via `asyncio.to_thread` to keep the event loop unblocked. Behavior-preserving; error responses now map the SDK's typed exceptions to HTTP status codes.

#### Fixed
- `media.csv` timestamps that mix timezone-aware and timezone-naive values (or different UTC offsets) no longer crash `/api/fs/inspect` and `/api/setup` with `ValueError: Mixed timezones detected` — `normalise_ts()` now strips any UTC offset/`Z` suffix before parsing, since every caller only uses the resulting timestamp as wall-clock local time (sampling occasion assignment, burst gaps, display), never as an absolute instant.
- The Linux `.deb`/`.rpm` package build no longer fails with `Git executable not found` — the build image now installs `git`, needed since `wildintel-trapper-sdk` is a git-sourced dependency.
- macOS installation instructions (Gatekeeper workaround) rewritten to use only GUI steps (double-click, System Settings → Privacy & Security → Open Anyway), removing the terminal-based quarantine-removal alternative.
- The **Minimum detection score** setting was never applied to the review workflow — `build_candidates()` had no `min_score` parameter, so events were included regardless of confidence. Frames whose own classification probability falls below the configured threshold are now demoted before bursts are grouped, matching the reference R tool's per-frame `to_camtrapdp()` threshold (a frame with no score at all is never demoted).
- `/api/image/{mediaID}` now sends `Cache-Control: no-store`, so the browser always revalidates against the backend instead of reusing a previously cached image for the same mediaID — a stale browser cache could otherwise keep showing a photo after it was moved or deleted between sessions.
- **Show all event frames** no longer collapses to a zero-width time window for detection events with a single target-species frame (the dominant case) — the burst window is now padded by `gap_seconds` on each side before looking up neighbouring frames, matching the reference R tool, so those events can actually show context frames instead of silently showing none.
- Frames sharing the exact same timestamp within a burst (e.g. second-resolution timestamps from some exports) are now ordered by a trailing numeric suffix in the file name (`..._1.JPEG` → 1) instead of an arbitrary order, matching the reference R tool's capture-order tiebreak.
- `deepfaune_to_camtrapdp()` had the confidence-score column name hardcoded to `score`, so a caller using DeepFaune's older `predictionbase`/`scorebase` columns directly (bypassing the API router's rename workaround) would silently get `NaN` scores. A `score_col` parameter now makes it configurable, same as `label_col`. The "Convert DeepFaune CSV" step also now shows which columns were auto-detected (`predictionbase`/`scorebase` vs. `top1`/`score`) instead of converting silently.
- `predictionbase`/`scorebase` (DeepFaune's per-image base classifier) now take priority over `top1`/`score` when a CSV has both, matching the reference R tool — previously `top1`/`score` always won, silently ignoring `predictionbase`/`scorebase`.
- The in-process flat-search file index (used when the *Images directory* option's subfolder search is enabled) is now cleared at the start of every `/api/setup`, so starting a new session no longer risks resolving images against a listing scanned before files were added, moved, or removed on disk.
